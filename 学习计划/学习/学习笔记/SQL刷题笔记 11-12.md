## 一、181 超过经理收入的员工

**标签**：自连接、INNER JOIN

### 题目需求
找出薪资高于自己经理的员工，经理信息在同一张 Employee 表。

**表结构**：`Employee (id, name, salary, managerId)`，`managerId` 是本表员工 id。

### 正确 SQL（例子）
```sql
SELECT e.name AS Employee
FROM Employee e
JOIN Employee m 
ON e.managerId = m.id
WHERE e.salary > m.salary;
```

### 核心思路（概念）
- 经理和员工数据在**同一张表**，一行数据拿不到另一行的字段，必须**自连接**：一张表起两个别名，逻辑拆成「员工表 e」「经理表 m」。
- 连接条件：员工的 `managerId = 经理的 id`；筛选：员工薪资 > 经理薪资。
- `INNER JOIN` 会自动过滤 `managerId` 为 NULL 的顶层管理者（没有经理，不需要对比）。

### 知识点
- **自连接适用信号**：字段指向本表主键，需要拿同表其他行的数据对比。
- 常见场景：员工-经理、分类-父分类、订单-父订单。

### 易错点（我卡在哪）
- 不要把 `managerId` 当成工资，它只是编号。
- 一开始容易卡在**单表 WHERE 里写条件**：单条记录只有本人信息，取不到经理薪资，做不到。

## 二、182 查找重复的电子邮箱

**标签**：GROUP BY、HAVING、聚合 COUNT()

### 题目需求
找出出现至少 2 次的邮箱。

**表结构**：`Person(id, email)`

### 正确 SQL（例子）
```sql
SELECT email AS Email
FROM Person
GROUP BY email
HAVING COUNT(*) > 1;
```

### 核心思路（概念）
按邮箱分组，统计每组行数；分组之后筛选分组结果，用 `HAVING`。

### 重点：WHERE 和 HAVING 区别（高频考点）
SQL 执行顺序：`FROM → WHERE → GROUP BY → 聚合计算 → HAVING → SELECT → ORDER BY`

| 关键字 | 作用 | 能否写聚合函数 |
|---|---|---|
| `WHERE` | 分组**之前**，过滤原始单行数据 | ❌ 不能写 COUNT/SUM/MIN/MAX |
| `HAVING` | 分组**之后**，过滤整个分组 | ✅ 可以用聚合函数 |

口诀：**行筛 where，组筛 having；聚合放 having**。

### 补充：COUNT(*) 跟着 GROUP BY 走
- 无 `GROUP BY`：`COUNT(*)` 统计**整张表**行数。
- 有 `GROUP BY`：`COUNT(*)` **每个分组单独计数**（统计当前组内行数）。

### 易错点（我卡在哪）
- ❌ `WHERE COUNT(*) > 1` 语法报错（WHERE 里不能写聚合函数）。
- ❌ 混淆：`DISTINCT` 只是查询去重，**不能用来统计重复次数**。

## 三、183 从不订购的客户

**标签**：LEFT JOIN、IS NULL

### 题目需求
找出从来没有下过订单的客户。

**表**：`Customers (id, name)`、`Orders (id, customerId)`

### 正确 SQL（例子）
```sql
SELECT c.name AS Customers
FROM Customers c
LEFT JOIN Orders o
ON c.id = o.customerId
WHERE o.customerId IS NULL;
```

### 核心思路（概念）
- 要【左表存在、右表没有匹配记录】的数据，优先 `LEFT JOIN`。
- `LEFT JOIN` 规则：左表全部保留；右表匹配不到，右表字段填充 NULL。
- 筛选条件：右表关联字段 `IS NULL`。

### 两种写法对比
| 写法 | 评价 |
|---|---|
| `LEFT JOIN + IS NULL` | ✅ 推荐，稳定 |
| `NOT IN` | 理解即可，**有大坑**：子查询结果包含 NULL 时，`NOT IN` 直接返回空结果 |

```sql
SELECT name AS Customers
FROM Customers
WHERE id NOT IN (SELECT customerId FROM Orders);
```

### 易错点（我卡在哪）
- ❌ `INNER JOIN`：只会返回两边都匹配到的（有订单的客户），**和题意相反**。
- ❌ `= NULL`：判断空必须 `IS NULL`，`= NULL` 结果永远未知，匹配不到任何数据。

## 四、196 删除重复的电子邮箱

**标签**：DELETE、自连接删除、DML 语句

### 题目需求
删除重复邮箱，每个邮箱只保留 id 最小的一行。

**表**：`Person (id, email)`

### ✅ 推荐写法（自连接删除）
```sql
DELETE p1
FROM Person p1
INNER JOIN Person p2
ON p1.email = p2.email
WHERE p1.id > p2.id;
```
- 含义：`p1` 是要删除的行，`p2` 是保留的行；同一个邮箱，id 更大的是重复数据，删掉。

### ✅ 子查询写法（MySQL 需要嵌套一层临时表）
```sql
DELETE FROM Person
WHERE id NOT IN (
    SELECT t.min_id FROM (
        SELECT MIN(id) AS min_id FROM Person GROUP BY email
    ) t
);
```
- MySQL 限制：不能在 DELETE 的子查询里直接读取正在删除的表，套一层临时表绕开报错。

### DELETE 语法总结
**1. 单表删除**
```sql
DELETE FROM 表名 WHERE 条件;
```
- 不加 WHERE：清空整张表，高危！

**2. 多表连接删除**
```sql
DELETE 要删的别名
FROM 表1 别名1
JOIN 表2 别名2
ON 连接条件
WHERE 筛选条件;
```
- `DELETE` 后面写哪个别名，就删除哪张表的数据。

### 三个删除语句区分
| 语句 | 类型 | 作用 | 能否回滚 | 自增 id |
|---|---|---|---|---|
| `DELETE` | DML | 删除行 | 可以 | 不重置 |
| `TRUNCATE` | DDL | 清空全表 | 不可 | 重置 |
| `DROP TABLE` | DDL | 删整张表（结构+数据） | 不可 | — |

### 易错点（我卡在哪）
- 题目要求 `DELETE`，不要写成 `SELECT` 查询。
- 条件写反 `p1.id < p2.id`：会删掉**最小 id** 的行。
- `DELETE` 不能删除单独一列，只能删除整行。

### 和 182 对比
- 182：`SELECT` 查询，查出重复邮箱。
- 196：`DELETE` 修改表，删除重复行。

## 五、197 上升的温度

**标签**：自连接、日期函数 DATEDIFF

### 题目需求
找到当天温度比前一天高的记录 id。

**表**：`Weather (id, recordDate, Temperature)`

### 正确 SQL（例子）
```sql
SELECT w1.id AS Id
FROM Weather w1
JOIN Weather w2
ON DATEDIFF(w1.recordDate, w2.recordDate) = 1
WHERE w1.Temperature > w2.Temperature;
```

### 核心思路（概念）
- `DATEDIFF(a, b)`：MySQL 函数，返回日期 a 减去日期 b 的天数。
- `w1` 是后一天，`w2` 是前一天，相差天数 = 1。

### 易错点（我卡在哪）
- ❌ `ON w1.id = w2.id`：自己和自己对比，永远不成立。
- ❌ `w1.id = w2.id + 1`：id 不一定连续，**不能依靠 id 判断相邻日期**。
- 自连接不一定靠 id 关联，根据业务选择关联条件（日期 / 外键）。

## 六、511 游戏玩法分析 I

**标签**：GROUP BY + MIN()

### 题目需求
查询每个玩家第一次登录的日期。

**表**：`Activity (player_id, device_id, event_date, games_played)`

### ✅ 最简写法（面试优先写这个）
```sql
SELECT player_id, MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```
- 思路：按玩家分组，组内取日期最小值（最早登录时间）。
- 不需要 `HAVING`：只是提取每组聚合值，不需要过滤分组。

### 补充思路（自连接版本，了解即可，不推荐）
```sql
SELECT DISTINCT a1.player_id, a1.event_date AS first_login
FROM Activity a1
LEFT JOIN Activity a2
ON a1.player_id = a2.player_id AND a2.event_date < a1.event_date
WHERE a2.player_id IS NULL;
```

### 易错点（我卡在哪）
- ❌ `GROUP BY player_id, event_date`：分组粒度变成"玩家 + 日期"，每组只有一行，`MIN` 失效。

## 七、577 员工奖金

**标签**：LEFT JOIN、NULL、OR 逻辑

### 题目需求
奖金小于 1000 **或者** 没有奖金记录的员工。

**表**：`Employee (empId, name)`、`Bonus (empId, bonus)`

### 正确 SQL（例子）
```sql
SELECT e.name, b.bonus
FROM Employee e
LEFT JOIN Bonus b 
ON e.empId = b.empId
WHERE b.bonus < 1000 OR b.bonus IS NULL;
```

### 我的原始错误复盘
```sql
-- ❌ 错误写法
SELECT name, bonus
FROM employee e
JOIN bonus b 
ON e.empid = b.empid
WHERE b.bonus < 1000 AND b.bonus IS NULL;
```
- **错误 1**：`JOIN` = `INNER JOIN`，直接丢掉没有奖金的员工，中间结果根本不存在 bonus 为 NULL 的数据。
- **错误 2**：`AND` 逻辑矛盾——一个字段不可能同时 `<1000` 并且是 NULL；两个条件是**或关系，要用 OR**。

### 补充
- NULL 和数字比较（`< > =`）结果是**未知**，不会成立，必须单独写 `IS NULL`。
- 小技巧：`IFNULL(b.bonus, 0) < 1000`，把 bonus 为 NULL 替换成 0，简化条件。

## 八、连接类型总对比（背诵）

| 连接类型 | 规则 | 适用场景 | 对应题目 |
|---|---|---|---|
| `INNER JOIN`（JOIN） | 两边匹配成功才保留 | 两边都要有对应数据 | 181 |
| `LEFT JOIN` | 左表全部保留，右表匹配不到填 NULL | 需要左表全部数据，包含右表无记录 | 183、577 |

## 九、今日核心判断口诀

1. 同一行要拿本表别的行数据对比 → **自连接**
2. 统计每组次数、求每组最大/最小 → **GROUP BY + MIN/MAX/COUNT**
3. 筛选分组结果 → **HAVING**；筛选原始行 → **WHERE**
4. 找左表有、右表没有的数据 → **LEFT JOIN + IS NULL**
5. 删除重复数据、保留最值行 → **DELETE + 自连接**
6. 判断空：只能 **IS NULL**，不能 `= NULL`
7. AND：同时满足；OR：满足其一

## 十、易混点清单

1. 自连接不一定都是 `INNER JOIN`，根据需求选。
2. 不是所有 `GROUP BY` 都要写 `HAVING`，只有过滤分组才需要。
3. `NOT IN` 有 NULL 风险，优先 `LEFT JOIN`。
4. id 只是主键，业务相邻关系（日期相邻）不能默认 id 连续。
5. `DELETE` 是修改数据，不是查询，和 `SELECT` 场景完全分开。
