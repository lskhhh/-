## 1. 电话号码校验（正则 REGEXP）

### 概念（是什么）
- `REGEXP`：用**正则表达式**匹配字符串的**格式**，而不是做替换。
- 适用场景：校验字段是否符合某几种固定格式（如电话号码、邮箱、身份证号）。
- 和 `LIKE` 的区别：`LIKE` 只能做简单的通配符匹配，`REGEXP` 能表达更复杂的格式规则。

### 语法/用法（怎么写）
```sql
WHERE 字段 REGEXP '正则表达式'
```
常用正则符号：

| 符号 | 含义 |
|---|---|
| `^` | 字符串开头 |
| `$` | 字符串结尾 |
| `()` | 分组 |
| `\|` | 或者 |
| `[1-9]` | 匹配 1~9 中的任意一位 |
| `[0-9]` | 匹配 0~9 中的任意一位 |
| `{n}` | 前面的字符恰好出现 n 次 |

### 例子（跑过的代码）
题目：号码两种合法格式——纯 10 位数字 / `xxx-xxx-xxxx`；首位不能为 0。

```sql
SELECT id, name, phone_number
FROM contacts
WHERE phone_number REGEXP '^[1-9][0-9]{9}$|^[1-9][0-9]{2}-[0-9]{3}-[0-9]{4}$'
ORDER BY id;
```

正则拆解：
- `^[1-9][0-9]{9}$`：纯 10 位数字，第一位 1~9，后面 9 位任意数字。
- `^[1-9][0-9]{2}-[0-9]{3}-[0-9]{4}$`：`3位-3位-4位`，横杠位置固定。
- 两者用 `|` 连接，表示"满足其一即可"。

### 易错点（我卡在哪）
- ❌ 用 `REPLACE` 去掉横杠再校验**有漏洞**：会放行 `123-4567-890`（横杠位置不对，但去掉横杠后恰好是 10 位数字）。
- ✅ **正则是校验原始字符串格式**；`REPLACE` 只适合"不限制横杠位置"的场景。
- 记住 `^` 和 `$` 必须写，否则 `REGEXP` 是"包含即匹配"，会出现子串误判。

## 2. 窗口函数——累计求和（OVER）

### 概念（是什么）
- 窗口函数：在**不合并行**的情况下，给每一行额外算一个指标（累计值、排名、分组内对比等）。
- 核心区别：
  - `GROUP BY + 聚合`：多行**合并成一行**，结果行数减少。
  - 窗口函数 `OVER()`：**保留原始所有行**，每一行后面额外多一列计算结果。

### 语法/用法（怎么写）
```sql
函数() OVER([PARTITION BY 分组列] [ORDER BY 排序列])
```
- `PARTITION BY`：分组，每组独立计算（类似"组内单独开窗口"）。
- 没有 `PARTITION BY`：全部数据当作一个大窗口。
- `ORDER BY`：指定窗口内按什么顺序累计/排序。

### 例子（跑过的代码）
需求：计算累计利润。
```sql
SELECT
    profit_id,
    profit_date,
    profit,
    SUM(profit) OVER (ORDER BY profit_date) AS cumulative_profit
FROM daily_profits
ORDER BY profit_date;
```
说明：按 `profit_date` 排序，`SUM(profit)` 从最早日期一路累加到当前行，得到累计利润。

### 易错点（我卡在哪）
- 窗口函数**不能写在 `WHERE` 里**（它是在 WHERE 筛选之后才计算的，逻辑顺序问题）。
- 别和 `GROUP BY` 混淆：窗口函数是"每行都保留，额外多一列"，不会减少行数。

## 3. 数学函数 ABS / CEIL / FLOOR / ROUND

### 概念（是什么）
- 对数值做取绝对值、取整、四舍五入的常用函数，常用于数据处理和报表计算。

### 语法/用法（怎么写）
| 函数 | 作用 |
|---|---|
| `ABS(x)` | 绝对值 |
| `CEIL(x)` | 向上取整（往**大数**方向） |
| `FLOOR(x)` | 向下取整（往**小数**方向） |
| `ROUND(x, n)` | 四舍五入，保留 n 位小数 |

### 例子（跑过的代码）
```sql
SELECT
    id,
    value,
    ABS(value)   AS absolute_value,
    CEIL(value)  AS ceiling_value,
    FLOOR(value) AS floor_value,
    ROUND(value, 1) AS rounded_value
FROM numbers
ORDER BY id;
```

### 易错点（我卡在哪）
- `CEIL` / `FLOOR` 是**取整**，不是四舍五入——负数方向尤其容易记反：
  - `CEIL(-1.2) = -1`（往大数方向）
  - `FLOOR(-1.2) = -2`（往小数方向）
- `ROUND` 的第二参数是**保留几位小数**，省略则取整（四舍五入）。

## 4. 分组统计 + SUM / COUNT 区分

### 概念（是什么）
- `SUM`：**求和**（对某列数值累加）。
- `COUNT`：**数行数**（统计非空行数）。
- 求"平均值"不能用 `COUNT` 顶替 `SUM`，要 `SUM / COUNT`。

### 语法/用法（怎么写）
```sql
SELECT 分组列, 聚合函数(...) AS 别名
FROM 表
GROUP BY 分组列
ORDER BY 分组列;
```
口诀：**求总量用 SUM，数行数用 COUNT**。

### 例子（跑过的代码）
按性别、大学分组，统计人数和平均活跃天数：
```sql
SELECT gender, university,
       COUNT(device_id) AS user_num,
       ROUND(SUM(active_days_within_30) / COUNT(device_id), 1) AS avg_active_day,
       ROUND(SUM(question_cnt) / COUNT(device_id), 1)        AS avg_question_cnt
FROM user_profile
GROUP BY gender, university
ORDER BY gender, university;
```
说明：平均活跃天数 = 总活跃天数 / 人数，即 `SUM / COUNT`。

### 易错点（我卡在哪）
- ❌ `COUNT(字段)` 只能数"非空行数"，**不能用来求和/算平均值**。
- ✅ 平均值 = `SUM(总和) / COUNT(人数)`。
- 聚合函数必须搭配 `GROUP BY`；`SELECT` 里**非聚合字段**都要放进 `GROUP BY`，否则语法报错。

## 5. CASE 条件判断

### 概念（是什么）
- `CASE` 是 SQL 里的条件分支：从上到下判断，命中即停止。
- 类似编程里的 `if / else if / else`，用于给数据"贴标签"或分段。

### 语法/用法（怎么写）
```sql
CASE
    WHEN 条件1 THEN 结果1
    WHEN 条件2 THEN 结果2
    ...
    ELSE 默认结果
END AS 别名
```

### 例子（跑过的代码）
按年龄分段：
```sql
SELECT device_id, gender,
       CASE
           WHEN age < 20 THEN '20岁以下'
           WHEN age BETWEEN 20 AND 24 THEN '20-24岁'
           WHEN age >= 25 THEN '25岁及以上'
           ELSE '其他'
       END AS age_cut
FROM user_profile;
```

### 易错点（我卡在哪）
- `CASE` 顺序**从上到下**，命中就停止（条件范围重叠时顺序很关键）。
- `ELSE` 负责接收 `NULL` 或其他没被覆盖的情况，别漏写——漏了 `NULL` 会变成 `NULL`。

## 6. 按日统计刷题数量（DAY + 范围筛选）

### 概念（是什么）
- `DAY(date)`：从日期里取出"几号"（1~31）。
- 范围筛选优先用 `>= ... AND < ...`（左闭右开），**可以走索引**，比用 `MONTH()` 等函数更快。

### 语法/用法（怎么写）
```sql
DAY(日期字段)
WHERE 日期字段 >= '起始' AND 日期字段 < '结束'
```

### 例子（跑过的代码）
统计 2021 年 8 月每天刷题数：
```sql
SELECT
    DAY(date) AS day,
    COUNT(question_id) AS question_cnt
FROM question_practice_detail
WHERE date >= '2021-08-01' AND date < '2021-09-01'
GROUP BY DAY(date)
ORDER BY day;
```

### 易错点（我卡在哪）
- 用 `DAY(date)` 后，`GROUP BY DAY(date)` 也要一致。
- 边界用 `< '2021-09-01'`（左闭右开），避免漏掉/多算最后一天。
- 如果直接对 `date` 用函数（如 `DAY(date)`）会**失效索引**，范围筛选要放在 WHERE 里先缩小范围。

## 7. 次日留存率（重点背诵）

### 概念（是什么）
- 次日留存：某天活跃的用户，**第二天还活跃**的比例。
- 口径 = 匹配成功记录数 / 总活跃记录数。
- 核心三要素：`DISTINCT` 去重 + 自 `LEFT JOIN` + `DATE_ADD`。

### 语法/用法（怎么写）
- `DISTINCT device_id, date`：同一天多次刷题只算一次活跃（去重）。
- 自左连接：同一个用户，`b 日期 = a 日期 + 1 天`。
- `DATE_ADD(日期, INTERVAL 1 DAY)`：日期加一天。
- 为什么用 `LEFT JOIN`：保留 `a` 侧（基准日）所有记录，`b` 侧匹配不到的就是 `NULL`。

### 例子（跑过的代码）
```sql
SELECT ROUND(COUNT(b.device_id) / COUNT(a.device_id), 4) AS avg_ret
FROM (SELECT DISTINCT device_id, date FROM question_practice_detail) a
LEFT JOIN (SELECT DISTINCT device_id, date FROM question_practice_detail) b
    ON a.device_id = b.device_id
    AND b.date = DATE_ADD(a.date, INTERVAL 1 DAY);
```
说明：
- 分子 `COUNT(b.device_id)`：第二天还活跃的记录数。
- 分母 `COUNT(a.device_id)`：基准日的总活跃记录数。

### 易错点（我卡在哪）
- ⚠️ **致命笔误**：不要写成 `DATE_ADD(b.date, ...)`，必须是 `DATE_ADD(a.date, INTERVAL 1 DAY)`（拿基准日 +1 天去匹配次日）。
- `LEFT JOIN` 匹配不到的一侧字段是 `NULL`，`COUNT` 会**自动忽略 NULL**，所以分母用 `a`、分子用 `b` 才能算对留存率。
- 同一天多次活跃要先 `DISTINCT` 去重，否则口径会错。

## 8. SUBSTRING_INDEX 字符串分割

### 概念（是什么）
- `SUBSTRING_INDEX`：按**分隔符**精准截取字符串片段，避免 `LIKE` 的误匹配。
- 常用于解析"拼接字符串"（如 `180cm,75kg,27,male`）。

### 语法/用法（怎么写）
```sql
SUBSTRING_INDEX(字符串, 分隔符, n)
```
- `n > 0`：从左往右，取第 n 个分隔符**前面**的部分。
- `n < 0`：从右往左，取倒数第 |n| 个分隔符**后面**的部分。

### 例子（跑过的代码）
示例字符串：`180cm,75kg,27,male`
```sql
-- 取最后一段（性别）
SUBSTRING_INDEX(profile, ',', -1) AS gender

-- 嵌套取倒数第二段（年龄）
SUBSTRING_INDEX(SUBSTRING_INDEX(profile, ',', -2), ',', 1)
```
嵌套拆解：`SUBSTRING_INDEX(profile, ',', -2)` 先取"最后两段"（`27,male`），再对它用 `SUBSTRING_INDEX(..., ',', 1)` 取第一段，即 `27`。

### 易错点（我卡在哪）
- ❌ `LIKE '%male'` 会**误匹配到 `female`**（`female` 结尾也是 `male`）。
- 对比写法要写 `LIKE '%,male'`，并且**长条件放前面**（`female` 先判断）。
- ✅ 优先用 `SUBSTRING_INDEX`：精准截取，不会出现 `male/female` 这种子串包含坑。

## 9. 通用易错清单（考前看）

1. 聚合函数（`COUNT`/`SUM`）必须搭配 `GROUP BY`；`SELECT` 中非聚合字段放 `GROUP BY`。
2. `CASE` 顺序从上到下，命中就终止。
3. `LEFT JOIN` 匹配不到的一侧字段为 `NULL`，`COUNT` 会忽略 `NULL`。
4. 窗口函数不能写在 `WHERE` 里。
5. `SUBSTRING_INDEX` 不管分段奇数还是偶数，规则不变。
6. `LIKE` 模糊匹配注意子串包含问题（`male`/`female` 经典坑）。
