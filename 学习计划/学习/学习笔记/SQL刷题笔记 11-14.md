# MySQL 刷题笔记（聚合函数 / 行转列 / 笛卡尔积）

> 核心重点：连接、分组聚合、where/having、行转列、count 与 sum 坑、笛卡尔积、加权平均

---

## 一、聚合函数易错点（高频坑）

### 1. avg(单行表达式) vs avg(sum(...))

| 写法 | 含义 | 是否合法 |
|---|---|---|
| `avg(rating / position)` | 每行先算比值，再对所有比值求平均 | ✅ 合法 |
| `avg(sum(rating/position))` | 同层 GROUP BY 里嵌套聚合 | ❌ 语法报错 |

- `avg(rating / position)`：每行先算比值，再对**所有比值**求平均。
  - 示例：两行 `(5/2, 3/3)` → `avg(2.5, 1) = 1.75`。
- `avg(sum(...))` 的逻辑含义：先把组内所有比值加起来，再对总和求平均——但一组只有一个总和，avg 没有意义，所以 MySQL 直接报错。

✅ **合法的 avg 套 sum**：必须拆成子查询，内层先分组 sum，外层再 avg：
```sql
SELECT avg(s)
FROM (SELECT sum(x) AS s FROM t GROUP BY xxx) t;
```

### 2. count(条件) ❌ 、sum(条件) ✅（超级高频坑）

**MySQL 布尔规则**：条件成立 = `true` = 1；不成立 = `false` = 0。

- `count(表达式)`：只判断是不是 NULL，`0` 和 `1` 都不算空，**都会计数**。
  - `count(rating < 3)`：不管满足不满足，全部统计，**永远等于总行数**，不能用来统计符合条件条数。
- `sum(条件)`：累加 1、0，最终得到满足条件的行数。
  - `sum(rating < 3)`：满足就 +1，不满足 +0。

✅ **等价通用写法（所有数据库兼容，没有 MySQL 特性）**：
```sql
SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
```

✅ **如果非要用 count 实现条件统计**：把不满足的转为 null：
```sql
COUNT(IF(rating < 3, 1, NULL))
```

**口诀**：统计满足条件多少行 → `sum(条件)`；count 只认 null。

### 3. 加权平均

- 公式：`SUM(units * price) / SUM(units)`
- ❌ 不是简单 `AVG(price)`。
- 含义：**总金额 ÷ 总销量**，销量大的价格权重更高。
- 只有所有行 price 完全一样时，结果才等于 price。
- 示例：`(100*5 + 15*20) / (100+15) = 800/115 ≈ 6.96`。

### 4. count(*) 和 count(列) 区别

| 写法 | 含义 |
|---|---|
| `count(*)` | 统计行数，哪怕这一行全部是 null，也计数 |
| `count(字段)` | 只统计这个字段**不为 NULL** 的行 |

- LeetCode 1280 考点：笛卡尔积左连之后，统计考试次数必须写 `count(e.subject_name)`，不能写 `count(*)`，否则 0 次的会算成 1。

## 二、WHERE 和 HAVING（重中之重，执行顺序）

### 概念（是什么）
执行顺序：`FROM → JOIN → WHERE → GROUP BY → 聚合计算 → HAVING → SELECT → ORDER BY`

| 关键字 | 时机 | 适用 | 作用 |
|---|---|---|---|
| `WHERE` | 分组**之前** | 原始列（order_date、id、rating 等明细字段） | 先把不需要的行直接剔除，这些行不参与分组、求和 |
| `HAVING` | 分组**之后** | 只能写【分组字段】、【聚合函数 sum/avg/count】 | 过滤分组后的结果 |

### 易错点（我卡在哪）
- ❌ 不能在 `HAVING` 里写**明细字段**（如 `order_date`）。
- 原因：GROUP BY 之后，多条明细合并成一行，原始明细字段已经被合并，数据库不知道取哪一条的值。

**口诀**：where 筛行，having 筛组；原始字段放 where，聚合结果放 having。

### 例子（跑过的代码）
筛选 2 月订单，并且产品总销量 ≥ 100：
```sql
WHERE order_date >= '2020-02-01' AND order_date < '2020-03-01' -- 先挑2月订单
GROUP BY product_name
HAVING SUM(unit) >= 100; -- 分组求和之后，过滤总量
```

## 三、JOIN 连接相关

### 1. 自连接坑（1148 自己看自己文章）

题目需求：同一行 `author_id = viewer_id`。

❌ 错误写法：
```sql
FROM Views v1 INNER JOIN Views v2 ON v1.author_id = v2.viewer_id
```
- 问题：跨行匹配！A 行作者 = B 行浏览者，会匹配出错误数据，**不需要自连接**。

✅ 最简正确写法：
```sql
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY id;
```

**自连接适合**：需要一行和另一行**不同行**对比（比如 A 关注 B、B 关注 A）；**同一行判断不需要 join**。

### 2. CROSS JOIN 笛卡尔积（LeetCode 1280）

#### 概念（是什么）
- A 表每一行和 B 表每一行全部两两配对，生成所有组合，**不需要 on 条件**。
- 等价写法：`inner join` 不带 on。
- 使用场景：需要枚举全部组合（每个学生 × 所有科目，哪怕这个学生该科没考过）。

#### 标准流程
1. `Students CROSS JOIN Subjects` 得到全部【学生 + 科目】组合。
2. `LEFT JOIN Examinations` 匹配考试记录。
3. `count(考试表字段)` 统计次数，没有考试就是 0。

#### 易错点
- 笛卡尔积容易数据爆炸，**只有枚举全部组合场景才用**。

### 3. LEFT JOIN 作用

- 保留左边表所有行，右边匹配不到的字段为 NULL。
- 求"没有销售记录的产品输出 0"，必须 `LEFT JOIN`；`INNER JOIN` 会直接丢掉无匹配的数据。
- 关联条件区分：`on` 里写两张表关联规则，`where` 是过滤。

## 四、行转列（LeetCode 1179 重新格式化部门表）

### 概念（是什么）
按 id 分组，每个月份单独一列展示收入。

### 两种写法（效果一样）

✅ IF 版本：
```sql
SELECT id,
       SUM(IF(month = 'Jan', revenue, NULL)) AS Jan_Revenue,
       SUM(IF(month = 'Feb', revenue, NULL)) AS Feb_Revenue
FROM Department
GROUP BY id;
```

✅ CASE WHEN（通用，推荐面试写）：
```sql
SELECT id,
       SUM(CASE WHEN month = 'Jan' THEN revenue END) AS Jan_Revenue
FROM Department
GROUP BY id;
```

### 核心思路
- 同一 id 下，匹配到月份就取收入，否则 null；`sum` 聚合拿到该月收入。
- 这里 `sum` 也可以换成 `max`，因为 `(id, month)` 是主键，每个 id + 月份最多一条数据。

## 六、通用避坑清单（考前快速回看）

1. `GROUP BY` 后面不能放聚合别名、聚合函数，只能放原始字段。
2. 聚合不要嵌套在同层 SELECT（`avg(sum())` 同层报错）。
3. 百分比不要忘记 ×100。
4. 左连接想保留左表全部数据，过滤条件放 `on` 还是 `where` 要分清。
5. 要生成全部组合（学生 × 科目），优先想到 `cross join` 笛卡尔积。
6. 统计满足条件行数：`sum(条件)`，拒绝 `count(条件)`。
7. 时间筛选优先用 `>= and <`，避免 datetime 时分秒踩坑。
