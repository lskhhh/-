# SQL 刷题笔记（WHERE / HAVING / JOIN / UPDATE）

> 核心主线：WHERE 和 HAVING 的区别、连接查询陷阱、聚合函数、UPDATE、CASE、分组逻辑坑

---

## 一、WHERE vs HAVING（最高频考点）

### 概念（是什么）
| 关键字 | 时机 | 作用 | 能否写聚合函数 |
|---|---|---|---|
| `WHERE` | 分组**之前** | 过滤原始行（挑出哪些行参与后续分组） | ❌ 不能写 COUNT/MAX/SUM/AVG |
| `HAVING` | 分组**之后** | 过滤分组结果（挑出哪些分组保留） | ✅ 可以写聚合函数 |

### 易错点（我卡在哪）
❌ 经典错误——WHERE 里不能放 count：
```sql
-- 错误！WHERE 里不能放 count
SELECT customer_number FROM Orders WHERE count(*) > 1 GROUP BY customer_number;
```

### 两种实现方式对比

✅ **HAVING（简洁推荐）**
```sql
SELECT class FROM Courses GROUP BY class HAVING count(student) >= 5;
```

✅ **想用 WHERE**：必须先把子查询算出聚合结果变成一张派生表，外层 WHERE 过滤普通列：
```sql
SELECT customer_number
FROM (
    SELECT customer_number, COUNT(*) AS cnt
    FROM Orders
    GROUP BY customer_number
) t
WHERE t.cnt = 2;
```

### 口诀
**行过滤用 WHERE，组过滤用 HAVING；聚合判断放 HAVING，非要 WHERE 套一层子查询。**

## 二、JOIN 连接查询 & 空值 NULL 大坑（重点：607 销售员）

### 概念（是什么）
- `INNER JOIN`（JOIN）：只保留两边匹配成功的数据。
- `LEFT JOIN`：保留左表全部，右表匹配不上时，右表字段为 NULL。

### 致命坑：LEFT JOIN 后，WHERE 直接过滤右表字段
示例错题：查找完全没有和 RED 公司合作过的销售员。

❌ 错误写法：
```sql
SELECT s.name 
FROM SalesPerson s
LEFT JOIN Orders o ON s.sales_id = o.sales_id
LEFT JOIN company c ON o.com_id = c.com_id
WHERE c.com_id != 'RED';
```

**错误原因**：
- 没有订单的销售员，`c.com_id IS NULL`。
- `NULL != 'RED'` 结果是未知（unknown），会被 WHERE 直接丢弃。
- ⚠️ 就算写 `WHERE c.com_id != 'RED' OR c.com_id IS NULL` 依然错！原因：一个销售同时有 RED 订单 + 其他订单，这条 SQL 依然会把他保留，不符合题意（只要有一笔 RED 订单就要剔除）。

### ✅ 三种正确思路

**① NOT IN（简单好写）**
```sql
SELECT name
FROM SalesPerson
WHERE sales_id NOT IN (
    SELECT o.sales_id
    FROM Orders o
    JOIN company c ON o.com_id = c.com_id
    WHERE c.name = 'RED'
);
```

**② NOT EXISTS（性能稳定，推荐）**
```sql
SELECT s.name
FROM SalesPerson s
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE o.sales_id = s.sales_id AND c.name = 'RED'
);
```

**③ LEFT JOIN + GROUP BY + HAVING（JOIN 方案）**
```sql
SELECT DISTINCT s.name
FROM SalesPerson s
LEFT JOIN Orders o ON s.sales_id = o.sales_id
LEFT JOIN Company c ON o.com_id = c.com_id
GROUP BY s.sales_id, s.name
HAVING SUM(IF(c.name = 'RED', 1, 0)) = 0;
```

### 易错点（我卡在哪）
- `LEFT JOIN + WHERE` 筛选右表字段**极易踩空值坑**。
- "完全不存在某类记录" 优先 `NOT EXISTS` / `NOT IN`。

### 其他 JOIN 题目小结
- **1068 产品销售分析 I**：`Sales JOIN Product`，题目保证外键一定匹配，`INNER JOIN` 和 `LEFT JOIN` 结果一样，优先写 `JOIN`。
- **1075 项目员工 I**：`Project JOIN Employee`，求平均工龄 `AVG(experience_years)` 等价 `SUM/COUNT`，`AVG` 更简洁；保留小数 `ROUND(值, 2)`。

## 三、GROUP BY 分组高频考点 & 坑

### 概念（是什么）
`GROUP BY`：把相同分组字段的值合并成一组；`SELECT` 中非聚合列，必须出现在 `GROUP BY` 里面。

### 1. 多字段分组（1050 演员导演）
需求：演员 + 导演配对，统计同一对搭档合作 ≥ 3 次。

✅ 正确：
```sql
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING count(*) >= 3;
```
- ❌ 错误：只 `GROUP BY` 其中一列，统计逻辑完全错误。
- 要点：要按"一对组合"统计，**两个字段都要写进 `GROUP BY`**。

### 2. 聚合函数不能嵌套聚合（619 只出现一次的最大数字）
- ❌ 错误：`HAVING max(count(*))`，MySQL 不支持聚合里面套聚合。
- ✅ 正确思路：子查询先分组统计，外层再取 MAX：
```sql
SELECT MAX(num) AS num
FROM (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(*) = 1
) t;
```

### 3. 超级大坑：1084 销售分析 III
题目：找出**所有销售记录全部落在 2019Q1（1.1-3.31）**的产品。

❌ 错误写法（先用 WHERE 筛日期）：
```sql
SELECT p.product_id, p.product_name
FROM sales s 
JOIN Product p ON s.product_id = p.product_id
WHERE s.sale_date >= '2019-01-01' AND s.sale_date <= '2019-03-31';
```
漏洞：WHERE 提前删掉一季度以外的订单，无法判断产品在别的时间有没有售卖。只要有一笔一季度订单就会被查出，不符合"全部订单都在一季度"。

✅ 正确：先保留全部数据分组，用 MIN、MAX 判断区间：
```sql
SELECT p.product_id, p.product_name
FROM sales s 
JOIN Product p ON s.product_id = p.product_id
GROUP BY p.product_id, p.product_name
HAVING MIN(s.sale_date) >= '2019-01-01' AND MAX(s.sale_date) <= '2019-03-31';
```

**区分两个题型**：
- 只要**存在一条**满足条件 → `WHERE` 过滤行
- **全部行**都要满足条件 → 不能提前 `WHERE`，分组 + `MIN/MAX` 放到 `HAVING`

### 4. 分组配套聚合函数
| 函数 | 作用 |
|---|---|
| `COUNT(*)` | 统计分组行数（常用） |
| `COUNT(列名)` | 忽略 NULL 行 |
| `SUM()` | 求和 |
| `AVG()` | 平均值 |
| `MAX()` / `MIN()` | 最大 / 最小值 |

## 四、CASE / IF 表达式（查询 + UPDATE 都能用）

### 1. 610 判断三角形（SELECT 里 CASE）
三边条件：任意两边之和大于第三边。
```sql
SELECT *,
       CASE 
           WHEN x + y > z AND x + z > y AND y + z > x THEN 'Yes'
           ELSE 'No'
       END AS triangle
FROM Triangle;
```
补充：正数三边可简化为「最大边 < 另外两边之和」，但写三个不等式可读性最好，**面试优先写完整版**。

### 2. 627 变更性别（UPDATE SET 内部用 IF / CASE）
题型限制：单条 UPDATE、不能 SELECT、不能临时表。

```sql
-- IF 简写
UPDATE Salary
SET sex = IF(sex = 'm', 'f', 'm');

-- CASE 写法
UPDATE Salary
SET sex = CASE sex
    WHEN 'm' THEN 'f'
    WHEN 'f' THEN 'm'
END;
```

> UPDATE 的完整系统知识点见下一节【五、UPDATE 专项知识点】。

## 五、UPDATE 专项知识点（背诵）

### 概念（是什么）
`UPDATE` 属于 **DML（数据操纵语言）**，作用：修改表中已存在的数据，会改动原表数据，和 `SELECT`（只读）完全不同。

### 一、基础语法
```sql
UPDATE 表名
SET 列1 = 值1, 列2 = 值2
[WHERE 筛选条件];
```
- ✅ 必记：`WHERE` 控制改哪些行。
- ⚠️ **超级大坑**：省略 `WHERE` → 更新整张表所有行！线上绝对禁止。

示例：
```sql
UPDATE Salary
SET salary = salary + 1000
WHERE id = 1;
```

### 二、SET 后面可以写什么（重点，627 考点）
`SET` 右边可以是**常量、列运算、IF、CASE 表达式**。

简单运算：
```sql
UPDATE t SET num = num * 2;
```

IF 二分支（简洁）：
```sql
UPDATE Salary SET sex = IF(sex = 'm', 'f', 'm');
```

CASE 多分支（分支多时用）：
```sql
UPDATE Salary
SET sex = CASE sex
    WHEN 'm' THEN 'f'
    WHEN 'f' THEN 'm'
END;
```
- ⚠️ 注意：`CASE` 如果没有 `ELSE`，匹配不到时会赋值为 **NULL**。

### 三、单表 UPDATE 的限制
1. 不能直接在 `SET` 里写聚合函数 `COUNT/SUM/MAX`：
```sql
-- ❌ 错误
UPDATE t SET cnt = COUNT(*) WHERE id = 1;
```
如果要用聚合结果，必须套子查询。

2. NULL 判断：`WHERE col IS NULL`，不能写 `col = NULL`。

3. ENUM 枚举类型：赋值必须是枚举定义内的值，否则报错。
   - 如 `sex ENUM('m','f')`，只能赋 'm'/'f'。

### 四、多表关联 UPDATE（MySQL 特有，笔试高频）
**写法 1：JOIN 关联更新（推荐，可读性强）**
```sql
UPDATE t1
JOIN t2 ON t1.id = t2.id
SET t1.val = t2.val;
```
- 含义：用 t2 的数据更新 t1。
- ⚠️ 坑：如果一条 t1 匹配多条 t2，会反复覆盖，结果不确定！

**写法 2：子查询更新**
```sql
UPDATE t1
SET col = (SELECT col FROM t2 WHERE t2.id = t1.id)
WHERE EXISTS (SELECT 1 FROM t2 WHERE t2.id = t1.id);
```
- ❌ 经典报错：不能在子查询里同时更新和查询同一张表：
  `You can't update and select from the same table in a subquery`
- 解决：子查询外层再包一层派生表。

### 五、执行顺序（非常关键）
先 `WHERE` 筛选行 → 再 `SET` 赋值。
- 先用 WHERE 挑出符合条件的行，再对筛选出来的行执行 SET 修改。
- **不是先 SET 再判断 WHERE！**

### 六、事务角度（了解，面试加分）
- MySQL 默认自动提交（`autocommit=1`），执行 UPDATE 立刻生效。
- 手动事务：
```sql
BEGIN;
UPDATE ...;
COMMIT;    -- 提交，永久生效
ROLLBACK;  -- 回滚，撤销修改
```
- 刷题时不需要写事务，但要记住：UPDATE 是**可回滚**的修改操作。

### 七、做题时的题目限制套路（LeetCode 高频约束）
常见题干要求：**仅使用单个 update 语句，不使用 select、不使用临时表**。
👉 解法：逻辑写在 `SET` 后的 `CASE / IF` 里面，不能写子查询。

### 八、UPDATE 和 SELECT 里 CASE 的区别
| 场景 | 作用 |
|---|---|
| `SELECT` 里的 CASE | 只用来查询展示，**不改原数据** |
| `UPDATE` 里的 CASE | 直接**修改存储在表里的值** |
语法结构一样，但作用完全不同！

### 九、易错错题清单
1. 忘记 `WHERE` → 全表更新（最高频踩坑）。
2. 中文分号、中文比较符号。
3. 关联更新一对多匹配，结果不可控。
4. 子查询更新同表触发报错。
5. CASE 漏掉 ELSE，意外出现 NULL。

### 十、对比小结
| 语句 | 性质 | 过滤方式 |
|---|---|---|
| `SELECT` | 查询，只读 | `WHERE`/`HAVING` 过滤结果 |
| `UPDATE` | 修改，写数据 | `WHERE` 控制哪些行被修改 |

## 六、零散语法易错点（低级错误，尽量避免）

1. 符号：不等于是英文 `!=` / `<>`，不要中文感叹号 `！=`；分号必须英文 `;`。
2. NULL 判断：不能写 `col = null`，只能 `col IS NULL` / `col IS NOT NULL`。
3. `count(e.*)` 语法非法，正确是 `count(*)` / `count(列)`。
4. 子查询派生表必须起别名 `t`，否则报错。
5. `LIMIT 1`：取排序后的第一条（586 订单最多客户，题目保证唯一最大值）：
```sql
SELECT customer_number
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(*) DESC
LIMIT 1;
```
进阶：存在并列第一时，`LIMIT 1` 失效，要用子查询 + `MAX` 的方案。
