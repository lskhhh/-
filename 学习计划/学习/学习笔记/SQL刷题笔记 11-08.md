# SQL 刷题笔记（2026-11-08）

> 今日重点：UNION ALL、CASE WHEN、GROUP BY、多表联查、WHERE/HAVING、RIGHT JOIN

## 1. UNION ALL

### 概念（是什么）
把多条 SELECT 查询的结果**上下拼接合并**，保留全部数据、不去重；可以控制前后两段数据的顺序。
> 区别：UNION 会自动去重，本题场景不能用。

### 语法/用法（怎么写）
```sql
SELECT 字段 FROM 表 WHERE 条件1
UNION ALL
SELECT 字段 FROM 表 WHERE 条件2
```
要求：前后两个 SELECT 的**字段数量、顺序、类型**保持一致。

### 例子（跑过的代码）
```sql
SELECT device_id, gender, age, gpa 
FROM user_profile 
WHERE university = '山东大学'

UNION ALL

SELECT device_id, gender, age, gpa 
FROM user_profile 
WHERE gender = 'male';
```

### 易错点（我卡在哪）
- UNION ALL 后面不能直接写 `where`，必须跟**完整 SELECT 语句**
- 不要和 `WHERE 条件1 OR 条件2` 混淆：OR 是在同一结果集筛选、顺序混乱；UNION ALL 才能保证前一段数据全部在前、后一段在后
- 不要误用 `UNION`（会自动去重），题目要求不去重时会做错
- 拼接后外层加 `ORDER BY` 会打乱两段原本的顺序

## 2. CASE WHEN 分组（条件分支统计）

### 概念（是什么）
按自定义规则给行打上**分类标签**，再配合 GROUP BY 实现自定义分组统计（如划分年龄段、等级）。

### 语法/用法（怎么写）
```sql
CASE
    WHEN 条件1 THEN '标签1'
    WHEN 条件2 THEN '标签2'
    ELSE '标签3'
END AS 别名
```

### 例子（跑过的代码）
```sql
SELECT
    CASE
        WHEN age < 25 OR age IS NULL THEN '25岁以下'
        ELSE '25岁及以上'
    END AS age_cut,
    COUNT(*) AS number
FROM user_profile
GROUP BY age_cut;
```

### 易错点（我卡在哪）
- NULL 判断不能用 `age = NULL`，只能用 `age IS NULL`
- `null < 25` 结果依然是 null，不会命中，必须单独写 `OR age IS NULL`
- GROUP BY 必须带上 CASE 起的别名
- 比较运算符对 NULL 运算全部失效

## 3. GROUP BY

### 概念（是什么）
按一个/多个字段对原始数据分组，相同分组字段值的行归为一组；配合聚合函数（COUNT/AVG/SUM/MAX/MIN），**一组只输出一行**汇总结果。
> 核心：先分组，再聚合。

### 语法/用法（怎么写）
```sql
SELECT
    分组字段,
    聚合函数(其他字段) AS 别名
FROM 表名
[WHERE 分组前过滤原始行]
GROUP BY 分组字段1, 分组字段2
[HAVING 分组之后过滤聚合结果]
[ORDER BY ...]
```
规则：SELECT 里**非聚合的普通列，必须全部出现在 GROUP BY 后面**。

### 例子（跑过的代码）
```sql
-- 单字段分组：按学校分组，统计每个学校用户数
SELECT
    university,
    COUNT(*) AS user_cnt
FROM user_profile
GROUP BY university;
```

```sql
-- 多字段分组：学校 + 题目难度双维度分组
SELECT
    u.university,
    qd.difficult_level,
    ROUND(COUNT(q.question_id)/COUNT(DISTINCT q.device_id),4) AS avg_answer_cnt
FROM user_profile u
JOIN question_practice_detail q ON u.device_id = q.device_id
JOIN question_detail qd ON q.question_id = qd.question_id
GROUP BY u.university, qd.difficult_level;
```

```sql
-- CASE WHEN 自定义标签后分组
SELECT
    CASE
        WHEN age < 25 OR age IS NULL THEN '25岁以下'
        ELSE '25岁及以上'
    END AS age_cut,
    COUNT(*) AS number
FROM user_profile
GROUP BY age_cut;
```

### 易错点（我卡在哪）
- ❌ SELECT 出现普通字段，但没写在 GROUP BY 里（很多 OJ 严格模式直接报错）
- ❌ 聚合函数不能嵌套：`AVG(COUNT(...))` 非法，必须拆成子查询先分组聚合一层
- ❌ 多字段分组少写分组列：比如需要 `university, difficult_level`，只写了 `university` → 结果完全错误
- ❌ 混淆 WHERE 和 HAVING：WHERE 在 GROUP BY 前筛原始行；HAVING 在 GROUP BY 后筛聚合组，HAVING 里可以写聚合函数
- ❌ NULL 会**单独作为一个分组**！age 为 NULL 的行被分到单独一组，需用 CASE 单独处理
- ✅ GROUP BY 可以直接用 SELECT 里起好的别名（MySQL 支持，刷题常用）

## 4. 多表联查 + 双维度分组统计（学校 + 难度）

### 概念（是什么）
多张表通过关联键 JOIN，按多个字段同时分组，计算分组内聚合指标。
> 公式：平均答题量 = 该分组总答题次数 ÷ 该分组内答过题的独立用户数

### 语法/用法（怎么写）
```sql
-- 写法1：一步聚合（简洁刷题版）
SELECT 分组字段1, 分组字段2, ROUND(COUNT(字段)/COUNT(DISTINCT 去重字段),4)
FROM 表A
JOIN 表B ON A.key = B.key
JOIN 表C ON B.key = C.key
GROUP BY 分组字段1, 分组字段2
```

```sql
-- 写法2：子查询分层（逻辑清晰版，先用户粒度聚合）
SELECT 分组字段1, 分组字段2, ROUND(AVG(单用户统计值),4)
FROM (
    SELECT 分组1, 分组2, 用户id, COUNT(*) AS user_q_cnt
    FROM 多表join
    GROUP BY 分组1, 分组2, 用户id
) t
GROUP BY 分组1, 分组2
```

### 例子（跑过的代码）
```sql
-- 版本1：一步除法
SELECT
    u.university,
    qd.difficult_level,
    ROUND(COUNT(q.question_id)/COUNT(DISTINCT q.device_id),4) AS avg_answer_cnt
FROM user_profile u
JOIN question_practice_detail q ON u.device_id = q.device_id
JOIN question_detail qd ON q.question_id = qd.question_id
GROUP BY u.university, qd.difficult_level;
```

```sql
-- 版本2：子查询 AVG
SELECT
    university,
    difficult_level,
    ROUND(AVG(user_q_cnt),4) AS avg_answer_cnt
FROM
    (
        SELECT
            u.university,
            q.device_id,
            qd.difficult_level,
            COUNT(q.question_id) AS user_q_cnt
        FROM
            user_profile u
            INNER JOIN question_practice_detail q ON u.device_id = q.device_id
            INNER JOIN question_detail qd ON qd.question_id = q.question_id
        GROUP BY
            u.university,
            q.device_id,
            qd.difficult_level
    ) t
GROUP BY university, difficult_level;
```

### 易错点（我卡在哪）
- 内层子查询分组**必须带上 device_id**，否则会把同一学校同一难度下所有用户混在一起 count，计算错误
- 聚合函数不能嵌套：`avg(count())` 非法，需要拆分子查询
- 分母必须 `count(distinct device_id)`，不加 distinct 会重复统计同一个用户
- 题目要求保留 4 位小数，记得套 `ROUND(...,4)`
- GROUP BY 必须把所有非聚合的选中字段全部写上（university + difficult_level 两个）

## 5. WHERE 与 HAVING 区分

### 概念（是什么）
- **WHERE**：分组之前过滤原始行
- **HAVING**：分组聚合计算完成后，对分组结果过滤，可以用聚合函数

### 语法/用法（怎么写）
```sql
SELECT 字段, 聚合函数
FROM 表
WHERE 原始行筛选条件（不能写 avg/sum/count）
GROUP BY 分组字段
HAVING 聚合后的筛选条件（可以用聚合函数）
```

### 例子（跑过的代码）
```sql
SELECT 
    university,
    AVG(question_cnt) AS avg_question_cnt,
    AVG(answer_cnt) AS avg_answer_cnt
FROM user_profile 
GROUP BY university
HAVING avg_question_cnt < 5 OR avg_answer_cnt < 20;
```

### 易错点（我卡在哪）
- 筛选聚合结果写 `HAVING`，不是写在 `GROUP BY` 后面
- `WHERE` 里面不能写聚合函数（avg、sum 等）
- 一句话：**WHERE 筛行，HAVING 筛分组**

## 6. JOIN 右连接 RIGHT JOIN 坑点

### 概念（是什么）
右连接：以右边表为主表，保留右表全部记录，匹配左表数据；匹配不上时左表字段为 NULL。

### 语法/用法（怎么写）
```sql
SELECT 字段
FROM 左表 u
RIGHT JOIN 右表 q
ON u.id = q.id
```

### 例子（跑过的代码）
```sql
SELECT q.device_id, q.question_id, q.result 
FROM user_profile u 
RIGHT JOIN question_practice_detail q 
ON u.device_id = q.device_id 
WHERE u.university = '浙江大学';
```

### 易错点（我卡在哪）
- 把左表字段的筛选条件写在 `WHERE`，RIGHT JOIN 会**等价于 INNER JOIN**，丢失右连接语义
- 业务只是取符合条件的关联数据时，优先 `INNER JOIN`，可读性更好
- `ON` 后面加条件 和 `WHERE` 后面加条件，结果**完全不一样**
